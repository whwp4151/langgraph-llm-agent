This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

This is a personal, educational sandbox for learning LangChain / LangGraph, built as a numbered sequence of Jupyter notebooks (`1.langchain_vs_langgraph.ipynb` through `8.multi-agent.ipynb`). Each notebook builds on concepts from earlier ones — read them in numeric order to understand the progression:

1. `1.langchain_vs_langgraph.ipynb` — basic LangGraph `StateGraph` vs. plain LangChain
2. `2.retrieval.ipynb` — RAG basics with Chroma + LangSmith hub prompts
3. `3.2` → `3.7` — tools, internal (built-in) tools, chat history/memory, human-in-the-loop (`interrupt`/`Command`), and a stock-analysis multi-agent example
4. `3.rewrite.ipynb`, `4.self-rag.ipynb` — query rewriting and self-RAG (relevance/hallucination/helpfulness grading loops)
5. `7.paraller-agent.ipynb` — parallel branches in a graph (fan-out/fan-in via multiple edges from `START`)
6. `8.multi-agent.ipynb` — supervisor-style multi-agent graph that composes the two standalone tax agents below as subgraphs

Two notebooks' logic has been extracted into standalone `# %%`-delimited scripts (Jupyter-cell-style, runnable interactively in VS Code) so they can be imported as modules:

- `income_tax_graph.py` — builds a self-RAG graph (retrieve → check_relevance → generate → check_hallucination → check_helpfulness → rewrite loop) over `documents/income_tax.txt`, compiled and exported as `graph`.
- `real_estate_tax_graph.py` — builds a multi-step calculation graph (parallel `get_tax_base_equation`/`get_tax_deduction` → `calculate_tax_base` → `calculate_tax_rate`) over `documents/real_estate_tax.txt`, compiled and exported as `graph`.

`8.multi-agent.ipynb` imports both (`from income_tax_graph import graph as income_tax_agent`, `from real_estate_tax_graph import graph as real_estate_tax_agent`) and routes user queries to one of them with an LLM-based supervisor/router node.

`mcp_server.py` is a separate, unrelated `FastMCP` stdio server exposing trivial `add`/`multiply` tools — a minimal MCP example, not wired into the LangGraph agents.

## Architecture patterns used throughout

- **State**: every graph defines a `TypedDict` (`AgentState` or `MessagesState`) as the graph state; nodes are plain functions `(state) -> partial state dict`.
- **Conditional routing**: `graph_builder.add_conditional_edges(node, router_fn, {label: next_node})` where `router_fn` returns a `Literal[...]` string — used for relevance/hallucination/helpfulness grading loops (self-RAG pattern) and supervisor routing.
- **Retrieval**: Chroma vector stores persisted to disk per-domain (`income_tax_collection/`, `real_estate_tax_collection/`), embedded with `HuggingFaceEmbeddings(model_name="BAAI/bge-m3")`. These collections are `.gitignore`d and regenerated by loading + splitting the corresponding `documents/*.txt` file with `RecursiveCharacterTextSplitter`.
- **Prompts**: grading/RAG prompts are pulled at runtime from the LangSmith prompt hub via `langsmith.Client().pull_prompt(..., dangerously_pull_public_prompt=True)` (e.g. `rlm/rag-prompt`, `langchain-ai/rag-document-relevance`, `langchain-ai/rag-answer-helpfulness`) rather than defined inline.
- **LLM**: `ChatGoogleGenerativeAI` (Gemini, typically `gemini-2.5-flash`) via `langchain_google_genai`, requires `GOOGLE_API_KEY` in `.env` (loaded with `python-dotenv`).
- **Human-in-the-loop / memory**: later notebooks (`3.5`, `3.6`) use `MemorySaver` checkpointing and `langgraph.types.interrupt`/`Command` for pausing graphs on tool calls pending human approval.

## Environment / running notebooks

- Requires a `.env` file with `GOOGLE_API_KEY` (see `.gitignore` — `.env` is never committed).
- `requirements.txt` currently only lists `mcp==1.29.0`; it does **not** capture the LangChain/LangGraph stack the notebooks actually use (`langchain`, `langgraph`, `langchain-google-genai`, `langchain-chroma`, `langchain-huggingface`, `langchain-community`, `langchain-text-splitters`, `langsmith`, `yfinance`, `python-dotenv`, `pydantic`). Check the imports at the top of a notebook/script before assuming a package is available, and don't assume `requirements.txt` is authoritative.
- The `.venv` here (Python 3.14) currently only has the `mcp`/`pydantic`/`dotenv` packages installed — it was set up for `mcp_server.py`, not for running the LangChain notebooks.
- To run the MCP math server standalone: `python mcp_server.py` (stdio transport).
- `income_tax_graph.py` / `real_estate_tax_graph.py` can be run cell-by-cell (VS Code "Run Cell" on `# %%` blocks) or imported directly (`from income_tax_graph import graph`); importing rebuilds/loads the corresponding Chroma collection at import time.
